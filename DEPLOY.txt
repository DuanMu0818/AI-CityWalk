================================================================================
  AI CityWalk — 私有服务器部署完全指南（纯文本版）
================================================================================

适用系统：Debian 12 / Ubuntu 20.04+
预计耗时：30-60 分钟（含域名配置）


================================================================================
  一、架构概览
================================================================================

部署后的请求流向：

  用户浏览器
      │
      ▼
  Nginx (监听 80/443 端口)
      │
      ├── *.css, *.js, *.svg ... → 直接返回静态文件 (frontend/)
      │
      ├── /api/* → Gunicorn (127.0.0.1:5000，仅本机监听)
      │               │
      │               ├── DeepSeek API   → AI 生成路线概念
      │               ├── 腾讯地图 API    → 地理编码 + POI 搜索
      │               └── SQLite 文件    → 历史记录持久化
      │
      └── 其他路径 → index.html (单页应用兜底)

关键设计决策：

  设计                   原因
  ─────────────────────  ──────────────────────────────────
  Nginx 处理静态文件      比 Flask 快 10 倍，支持缓存和 gzip
  Gunicorn 只绑 127.0.0.1 不直接暴露公网，安全
  前端同源部署            前端 JS 自动用相对路径调 API
  腾讯地图 Key 动态获取    Key 存后端，不暴露在 HTML 源码
  SQLite 文件存储         零配置，不需要额外数据库服务


================================================================================
  二、前提准备
================================================================================

你需要准备：

  项目              说明                      去哪弄
  ───────────────── ───────────────────────── ──────────────────────────────
  服务器             Debian 12/Ubuntu，≥1核1G  阿里云/腾讯云/华为云 等
  域名（可选）        有域名才能上 HTTPS         任意域名注册商
  DeepSeek API Key   AI 生成路线的核心          platform.deepseek.com
  腾讯地图 Key        地图显示 + 地址搜索        lbs.qq.com

腾讯地图 Key 特别说明：
  这个 Key 需要同时开启两个服务：
  1. WebService API — 后端地理编码用
  2. 地图 JS API — 前端地图显示用

  在 lbs.qq.com 控制台的 Key 管理中：
  - 勾选 WebService API → 选择域名白名单 → 填入服务器 IP 或域名
  - 勾选 地图 JS API → 同样设置白名单

  ⚠ 白名单不设置的话，地图在前端加载不出来，地理编码也会被拒绝。
  这是部署失败最常见的原因。

SSH 登录服务器：
  ssh root@你的服务器IP
  （或）ssh -i ~/.ssh/你的密钥 root@你的服务器IP

  # 更新系统包

================================================================================
  六、第四步：配置环境变量
================================================================================

创建 .env 文件：
  cd /opt/AI-CityWalk/backend
  nano .env

写入以下内容（替换成你自己的 Key）：

  # DeepSeek AI 配置
  DEEPSEEK_API_KEY=sk-你的DeepSeek密钥

  # 腾讯地图配置
  TENCENT_MAP_KEY=你的腾讯地图Key

  # 数据库文件路径（可选，默认 backend/citywalk.db）
  DATABASE_PATH=/opt/AI-CityWalk/backend/citywalk.db

  # 运行端口（可选，默认 5000）
  PORT=5000

各变量说明：

  变量             必填  默认值                 说明
  ──────────────── ──── ────────────────────── ─────────────────────
  DEEPSEEK_API_KEY 是   -                      DeepSeek 平台 API Key
  TENCENT_MAP_KEY  是   -                      腾讯位置服务 Key
  DATABASE_PATH    否   backend/citywalk.db    SQLite 数据库文件位置
  PORT             否   5000                   Gunicorn 监听端口

安全设置：
  chmod 600 /opt/AI-CityWalk/backend/.env
  ls -la /opt/AI-CityWalk/backend/.env
  # 应该显示 -rw------- (600)


================================================================================
  七、第五步：手动启动验证
================================================================================

部署最重要的原则：先手动跑通，再配置自动启动。

启动后端：
  cd /opt/AI-CityWalk/backend
  source venv/bin/activate
  python app.py

看到以下输出说明成功：
  ✅ 所有 API Key 已配置
  🚶 AI CityWalk 后端启动中...
  📍 访问 http://localhost:5000

如果看到 "⚠ 警告：以下 API Key 未配置"，说明 .env 文件有问题。

测试 API（另开一个 SSH 窗口）：

  # 测试 1：获取配置
  curl http://localhost:5000/api/config
  # 预期返回：{"tencent_map_key":"你的Key"}

  # 测试 2：生成路线（核心功能全流程）
  curl -X POST http://localhost:5000/api/generate \
    -H "Content-Type: application/json" \
    -d '{"city":"成都","theme":"美食之旅","time_energy":"半天轻松逛（约3-4小时）"}'
  # 预期返回：完整路线 JSON，每个途经点都有 lat/lng 坐标

测试通过后，按 Ctrl+C 停掉。


================================================================================
  八、第六步：systemd 服务化
================================================================================

让应用后台持续运行，崩溃自动重启，服务器重启后自动启动。

创建服务文件：
  sudo tee /etc/systemd/system/citywalk.service << 'EOF'
  [Unit]
  Description=AI CityWalk Backend
  After=network.target

  [Service]
  Type=simple
  User=www-data
  Group=www-data
  WorkingDirectory=/opt/AI-CityWalk/backend
  EnvironmentFile=/opt/AI-CityWalk/backend/.env
  ExecStart=/opt/AI-CityWalk/backend/venv/bin/gunicorn app:app \
      --bind 127.0.0.1:5000 \
      --workers 2 \
      --timeout 120 \
      --access-logfile /var/log/citywalk-access.log \
      --error-logfile /var/log/citywalk-error.log
  Restart=always
  RestartSec=5

  [Install]
  WantedBy=multi-user.target
  EOF

参数说明：

  参数              值                    说明
  ────────────────  ────────────────────  ───────────────────────────
  User              www-data              低权限运行，更安全
  WorkingDirectory  /opt/.../backend       确保 .env 和 .db 能找到
  EnvironmentFile   .env 路径              加载环境变量
  --bind            127.0.0.1:5000         仅本机监听，不暴露公网
  --workers         2                      进程数，小服务器够了
  --timeout         120                    DeepSeek 有时响应慢
  Restart           always                 挂了自动拉起来
  RestartSec        5                      等 5 秒再重启

设置权限并启动：
  sudo chown -R www-data:www-data /opt/AI-CityWalk
  sudo touch /var/log/citywalk-access.log /var/log/citywalk-error.log
  sudo chown www-data:www-data /var/log/citywalk-access.log /var/log/citywalk-error.log
  sudo systemctl daemon-reload
  sudo systemctl enable citywalk
  sudo systemctl start citywalk
  sudo systemctl status citywalk

看到 "Active: active (running)" 就对了。

如果 Active: failed，排查：
  sudo journalctl -u citywalk -n 50 --no-pager
  sudo tail -50 /var/log/citywalk-error.log


================================================================================
  九、第七步：Nginx 反向代理
================================================================================

创建站点配置：
  sudo tee /etc/nginx/sites-available/citywalk << 'EOF'
  server {
      listen 80;
      server_name 你的域名或IP;    # ← 改成你自己的

      root /opt/AI-CityWalk/frontend;
      index index.html;

      # 静态资源缓存 7 天
      location ~* \.(css|js|svg|png|jpg|jpeg|gif|ico|woff|woff2)$ {
          expires 7d;
          add_header Cache-Control "public, immutable";
      }

      # API 请求转发给 Gunicorn
      location /api/ {
          proxy_pass http://127.0.0.1:5000;
          proxy_set_header Host $host;
          proxy_set_header X-Real-IP $remote_addr;
          proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
          proxy_set_header X-Forwarded-Proto $scheme;
          proxy_read_timeout 120s;
          proxy_connect_timeout 30s;
      }

      # 其他路径返回 index.html
      location / {
          try_files $uri $uri/ /index.html;
      }

      # 禁止访问隐藏文件
      location ~ /\. {
          deny all;
          access_log off;
          log_not_found off;
      }
  }
  EOF

启用站点：
  sudo ln -s /etc/nginx/sites-available/citywalk /etc/nginx/sites-enabled/
  sudo rm -f /etc/nginx/sites-enabled/default
  sudo nginx -t               # 检查语法
  sudo systemctl reload nginx
  sudo systemctl status nginx

浏览器访问 http://你的服务器IP，应该能看到完整的 AI CityWalk 页面。


================================================================================
  十、第八步：防火墙配置
================================================================================

云服务器安全组（先做这个）：
  如果你用的是阿里云/腾讯云/华为云等，登录云控制台，在安全组中添加：

  方向      端口   协议   来源
  ────────  ────  ────  ───────────
  入方向    80    TCP   0.0.0.0/0
  入方向    443   TCP   0.0.0.0/0
  入方向    22    TCP   你的IP      （SSH，别把自己锁外面）

  ⚠ 安全组是云平台层面的防火墙，和系统防火墙是两层，都要放行。

Debian 12 系统防火墙：
  # 查看当前规则
  sudo nft list ruleset

  # 如果输出为空，说明没开防火墙，不用管
  # 如果有规则，添加放行：
  sudo nft add rule inet filter input tcp dport 80 accept
  sudo nft add rule inet filter input tcp dport 443 accept


================================================================================
  十一、第九步：HTTPS 证书
================================================================================

需要先有域名，并解析到服务器 IP。

  # 修改 Nginx 配置中的 server_name
  sudo nano /etc/nginx/sites-available/citywalk
  # 把 server_name 改成你的域名，例如 citywalk.你的域名.com

  sudo nginx -t && sudo systemctl reload nginx

  # 申请免费 SSL 证书
  sudo certbot --nginx -d 你的域名

  # 按提示操作：
  # 1. 输入邮箱（证书到期提醒用）
  # 2. 同意服务条款（Y）
  # 3. 是否接收推广（N）
  # 4. 是否自动跳转 HTTPS（选 2）

完成后访问 https://你的域名，地址栏应出现 🔒 图标。

证书 90 天有效期，certbot 会自动续期。验证一下：
  sudo certbot renew --dry-run
  # 看到 "Congratulations, all simulated renewals succeeded" 就 OK

================================================================================
  十三、故障排查
================================================================================

问题 1：访问页面 502 Bad Gateway
  原因：Nginx 正常，但后端 Gunicorn 挂了。

  排查：
    sudo systemctl status citywalk
    sudo journalctl -u citywalk -n 50

  常见原因：
    - .env 文件不存在或路径不对
    - Python 依赖没装全 → pip install -r requirements.txt
    - www-data 权限不对 → sudo chown -R www-data:www-data /opt/AI-CityWalk

问题 2：404 Not Found
  原因：Nginx root 路径不对或站点没启用。

  排查：
    ls -la /opt/AI-CityWalk/frontend/index.html
    ls -la /etc/nginx/sites-enabled/
    sudo nginx -t

问题 3：504 超时
  原因：AI 生成超时 > Nginx proxy_read_timeout。

  排查：
    grep "proxy_read_timeout" /etc/nginx/sites-available/citywalk
    # 应该是 120s，太小就改大
    grep "timeout" /etc/systemd/system/citywalk.service
    # 也应该是 120

问题 4：地图加载不出来
  原因：腾讯地图 Key 白名单没配。

  排查：
    1. F12 控制台看有没有 "key 鉴权失败"
    2. 去 lbs.qq.com → Key 管理 → 检查白名单
    3. 检查是否同时开启了 WebService API 和地图 JS API

问题 5：定位返回 "IP 定位失败"
  原因：腾讯地图 IP 定位接口调用失败。

  排查：
    curl "https://apis.map.qq.com/ws/location/v1/ip?key=你的Key"
    # 返回 status: 0 说明正常

问题 6：历史记录刷新后丢失
  原因：数据库路径或权限问题。

  排查：
    ls -la /opt/AI-CityWalk/backend/citywalk.db
    sudo -u www-data sqlite3 /opt/AI-CityWalk/backend/citywalk.db \
        "SELECT COUNT(*) FROM routes;"

问题 7：Gunicorn workers 不够用
  症状：多用户同时访问响应慢。

  解决：
    sudo nano /etc/systemd/system/citywalk.service
    # 把 --workers 2 改成 --workers 4
    sudo systemctl daemon-reload
    sudo systemctl restart citywalk

  Workers 建议值：CPU 核数 × 2 + 1（nproc 查看核数）

通用排查：
  curl -v http://127.0.0.1:5000/api/config     # 绕过 Nginx 测后端
  curl -v http://localhost/api/config           # 通过 Nginx 测
  sudo journalctl -p 3 -xb                      # 系统级错误


================================================================================
  十四、Debian 12 vs Ubuntu 差异
================================================================================

  差异点           Debian 12          Ubuntu 22.04       影响
  ───────────────  ─────────────────  ─────────────────  ──────────
  默认 Python      3.11 (完美)       3.10               都能用
  www-data 用户    存在               存在                无差异
  Nginx 配置路径   sites-available    相同                无差异
  systemd 路径     systemd/system     相同                无差异
  默认防火墙       nftables(无规则)   ufw(未启用)        基本不用管
  certbot 包名     certbot            相同                无差异

结论：本指南同时适用于 Debian 12 和 Ubuntu，命令完全通用。
